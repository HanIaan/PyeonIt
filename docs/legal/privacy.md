# 편잇 개인정보처리방침 (초안)

> **법률 자문이 아니라 검토용 초안입니다.** 실제 코드·설정(2026-11-08 기준 main)을 근거로 작성했으며, 시행 전 전문가 검토가 필요합니다. `[미정: …]`은 운영자가 정해야 할 값, `[확인 필요: …]`는 정책 결정이나 법령 확인이 필요한 부분입니다.

[미정: 운영자 이름 또는 상호](이하 "운영자")는 편잇 서비스(이하 "서비스")를 운영하면서 이용자의 개인정보를 관련 법령에 따라 처리합니다. 이 방침은 서비스가 어떤 정보를 어떻게 처리하는지 설명합니다.

## 1. 처리하는 개인정보 항목

서비스는 이메일, 실명, 전화번호, 생년월일, 프로필 사진을 **저장하지 않습니다.** 실제로 저장하는 항목은 아래와 같습니다.

### 1.1 회원 가입·로그인

| 항목 | 내용 |
|---|---|
| 소셜 로그인 식별자 | 로그인 제공자 종류(카카오·구글)와 제공자가 발급한 이용자 고유 ID, 연결 일시 |
| 닉네임 | 이용자가 정한 닉네임, 마지막 변경 일시 |
| 회원 상태 | 회원 번호, 권한(일반·관리자), 상태(정상·정지·탈퇴), 가입 일시, 탈퇴 일시 |

- 카카오 로그인은 이용자 고유 ID만 받아 저장하며 이메일을 받지 않도록 설정되어 있습니다.
- 구글 로그인은 구글이 인증 과정에서 이메일 등 기본 프로필 정보를 서비스 서버에 전달할 수 있으나, 서비스는 그중 구글 고유 ID만 저장합니다. [확인 필요: 구글 요청 범위(scope)를 최소화할지]

### 1.2 서비스 이용 과정

| 항목 | 내용 |
|---|---|
| 관심 대학 | 이용자가 등록한 관심 대학과 등록 일시 |
| 게시글 | 게시판, 제목, 본문, 관련 대학, 상태(게시·숨김·삭제), 조회수·추천수·댓글수, 작성·수정 일시 |
| 댓글 | 본문, 상위 댓글, 상태, 작성·수정 일시 |
| 추천 | 추천한 게시글과 일시 |
| 업로드 이미지 | 이미지 파일 자체, 저장 키(무작위 UUID 파일명), 형식, 크기, 업로드한 회원, 업로드 일시 |
| 신고 | 신고자, 신고 대상(게시글·댓글·회원), 사유, 상세 내용(최대 500자), 처리 상태·처리자·처리 일시 |
| 제재 | 제재 대상 회원, 종류(경고·정지·무기한 정지), 사유(최대 500자), 시작·종료 일시, 제재한 관리자 |
| 제재 회피 방지 정보 | 정지 중 탈퇴한 경우, 소셜 로그인 식별자를 비밀 키로 HMAC-SHA256 처리한 해시값과 만료 일시 (원래 식별자와 회원 번호는 함께 저장하지 않음) |

### 1.3 푸시 알림(이용자가 켠 경우)

| 항목 | 내용 |
|---|---|
| 푸시 구독 정보 | 브라우저 푸시 서비스의 구독 주소(endpoint), 암호화 키(p256dh, auth), 브라우저 정보(User-Agent, 최대 500자), 구독 일시, 마지막 발송 성공 일시 |
| 알림 설정 | 새 모집요강 알림, 일정 리마인더 알림 수신 여부 |
| 발송 기록 | 알림 종류, 대상 모집요강·일정 번호, 발송 시도 일시 |

### 1.4 자동으로 생성·처리되는 정보

- **세션 쿠키(`JSESSIONID`)**: 로그인 상태 유지. 자세한 내용은 7조를 참고하세요.
- **CSRF 쿠키(`XSRF-TOKEN`)**: 위조 요청 방지용 토큰.
- **IP 주소·세션 ID(검색 요청 제한용)**: 검색 남용을 막기 위해 일정 시간(기본 60초) 동안 요청 수를 셉니다. 이 값은 서버 메모리에만 잠시 있고 데이터베이스에 저장하지 않으며, 시간 창이 지나면 지워집니다.
- [확인 필요: 웹 서버·프록시·호스팅 접속 로그(IP 등) 수집 여부와 보관 기간. 애플리케이션 코드에는 별도 접속 로그 저장이 없음]

## 2. 수집 방법

- 소셜 로그인 시 카카오·구글로부터 고유 ID를 받습니다.
- 이용자가 가입·닉네임 변경·글쓰기·이미지 업로드·신고·알림 설정 때 직접 입력합니다.
- 푸시 알림을 켜면 브라우저가 구독 정보를 만들고, 웹 화면이 이를 브라우저 정보와 함께 서버로 보냅니다.

## 7. 쿠키

| 쿠키 | 용도 | 속성 |
|---|---|---|
| `JSESSIONID` | 로그인 세션 유지 | HttpOnly, SameSite=Lax, 운영 환경 Secure, 도메인 [미정: 운영 도메인]. 로그아웃·탈퇴 시 세션 종료 |
| `XSRF-TOKEN` | 위조 요청(CSRF) 방지 | SameSite=Lax. 웹 화면이 읽어야 하므로 HttpOnly가 아님 |

- 세션 유지 시간: 별도로 설정하지 않아 서버 기본값을 따릅니다. [확인 필요: 세션 만료 시간 명시]
- 광고·분석용 쿠키는 쓰지 않습니다. [확인 필요: 웹에 분석 도구를 넣을 경우 이 조항 갱신]
- 거부 방법: 브라우저 설정에서 쿠키를 차단할 수 있습니다. 다만 두 쿠키는 로그인과 글쓰기에 꼭 필요하므로, 차단하면 로그인이 필요한 기능을 쓸 수 없습니다. 비로그인 열람은 가능합니다.

## 8. 이미지 업로드 시 유의사항

- JPEG, PNG, WebP, GIF만 올릴 수 있고, 한 장 최대 5MB, 게시글당 최대 10장입니다.
- 파일 이름은 서버가 무작위 이름(UUID)으로 바꾸므로 원래 파일 이름은 저장되지 않습니다.
- **올린 이미지는 로그인 없이 누구나 볼 수 있는 공개 주소로 제공됩니다.**
- **서비스는 사진의 메타데이터(EXIF, 촬영 위치 GPS 등)를 지우지 않고 원본 그대로 저장합니다.** 위치 정보 등이 담긴 사진은 올리기 전에 직접 지워 주세요. [확인 필요: 서버에서 메타데이터 제거 여부]
- 본인이나 다른 사람의 얼굴, 수험표, 성적표, 연락처 등 개인정보가 보이는 이미지는 올리지 마세요.

## 9. 파기 절차와 방법

- 보유 기간이 끝났거나 처리 목적을 달성한 정보는 지체 없이 파기합니다.
- 데이터베이스의 정보는 복구할 수 없도록 삭제합니다. 탈퇴 시 닉네임은 지우고 소셜 로그인 식별자 행은 삭제합니다.
- 이미지 파일은 저장소(Cloudflare R2)에서 객체를 삭제합니다.
- 자동 파기: 연결 안 된 이미지(24시간, 1시간마다 확인), 만료된 제재 회피 방지 해시(매일).
- [확인 필요: 백업본 파기 절차, 종이 문서 등 기타 파기 방법]

## 11. 안전성 확보 조치

코드와 설정으로 확인되는 조치는 다음과 같습니다.

- 제재 회피 방지 정보는 원래 소셜 ID가 아닌 HMAC-SHA256 해시로만 저장하고, 해시 키는 운영 환경에서 필수이며 개발용 키 사용을 막습니다.
- 세션 쿠키에 HttpOnly·SameSite=Lax를 적용하고, 운영 환경에서 Secure(HTTPS 전용)를 적용합니다.
